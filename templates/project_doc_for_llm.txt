## 📉 Business Problem

Ride-share and taxi operators face significant challenges in managing the supply-demand balance across urban zones. Customer demand fluctuates dynamically across hours of the day, days of the week, seasons, and in response to local events or weather. Without accurate forecasting, companies experience:

- **Under-supply** → long waits, missed trips, churn  
- **Over-supply** → idle time, fuel waste, lower driver earnings  
- **Reactive pricing** instead of planned incentives  
- **Inequitable service** across zones and time windows  

Operators including Uber, Lyft, Ola, and local taxi services must efficiently forecast demand to optimize resource allocation and improve overall service.

## 2. Data Description

### Data Sources
- **Weather Data:** Hourly meteorological data via Open-Meteo API for NYC (Jan–Apr 2025).  
- **Traffic Data:** NYC taxi trip records (monthly Parquet files) with pickup times, locations, and ride counts.  

### Data Preprocessing
- **Missing Values:** Numeric features imputed with zeros; datetime fields filled with Unix epoch placeholder.  
- **Categorical Encoding:** Ordinal encoding for `PULocationID`, `weathercode`, `hour`, `day_of_week`, `month`.  
- **Scaling:** Standard scaling for numerical features (temperature, precipitation, lag, rolling stats).

## 3. Feature Descriptions

| Feature                | Description                                                                                     |
|------------------------|-------------------------------------------------------------------------------------------------|
| **pickup_hour**        | Timestamp rounded to the hour, including timezone info.                                         |
| **PULocationID**       | Integer representing NYC taxi pickup zone.                                                     |
| **temperature_2m**     | Air temperature at 2 meters, °C.                                                              |
| **precipitation**      | Total precipitation during the hour, mm.                                                      |
| **weathercode**        | Weather condition code (clear, rain, snow, etc.).                                              |
| **hour**               | Integer hour of day (0–23).                                                                   |
| **day_of_week**        | Integer day of week (0=Mon, 6=Sun).                                                           |
| **month**              | Integer month (1–12).                                                                         |
| **is_weekend**         | Binary indicator for weekend.                                                                  |
| **date**               | Calendar date extracted from pickup_hour.                                                     |
| **is_holiday**         | Binary indicator for public holidays.                                                         |
| **ride_count_lag_1**   | Ride count 1 hour prior at same location.                                                     |
| **ride_count_lag_24**  | Ride count 24 hours prior, same hour/location.                                                |
| **ride_count_lag_168** | Ride count 1 week prior, same hour/location.                                                 |
| **ride_count_roll_mean_3** | Rolling mean of past 3 hours (excluding current).                                           |
| **ride_count_roll_std_3**  | Rolling std deviation of past 3 hours.                                                     |
| **is_rain**            | Binary flag (1 if precipitation > 0).                                                        |
| **ride_count**         | Actual observed number of rides (target variable).                                           |

## 4. Model Description

### Framework & Implementation
- **TensorFlow** with GPU acceleration.  
- Embedding layers for high-cardinality categorical variables.  
- Fully connected dense layers with **ReLU** activations; linear output for ride count prediction.  

### Training Procedure
- Train/validation split: 80/20.  
- Batch size: 1024; Epochs: 10.  
- **Keras Tuner RandomSearch** for embedding sizes, dense units, dropout, learning rate.  
- Final model retrained on full dataset.

### Model Performance

| Metric                         | Value       |
| ------------------------------ | ----------- |
| MAE                            | 5.55        |
| MSE                            | 157.81      |
| RMSE                           | 12.56       |
| R²                             | 0.972       |
